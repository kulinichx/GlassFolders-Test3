# GlassFolders 离线授权与系统适配

这是独立于 RC7 的 GlassFolders 授权版本。设备端只含公钥；签发私钥保留在 Windows 签发器中。RC7 的授权、绑定码与设备回执不能用于本产品。

先阅读 [安装状态与激活指南](安装状态与激活指南.md)，了解旧包与新授权版的区别，以及手机和电脑的逐步操作。电脑签发器直接双击 `GlassFolders签发器.exe`，不需要 CMD 窗口。

## 当前交付状态

- 本分支为 `1.1.0~license1` 候选版，目标 iOS / iPadOS **16.0–17.3.1**。
- Windows 签发逻辑已通过自动检查，含独立 Node/OpenSSL 与 Windows CNG 双向签名验证。
- 当前 Windows 工作环境没有 Apple SDK/Theos 编译环境；尚未编译此候选版，也没有连接设备完成真机验证。仓库中的构建流程用于产生 RootHide 与标准 rootless 两种安装包。
- 原有 `1.0.0-fix1` 安装包没有本次新增的授权功能，不能拿它测试新授权。

## 激活步骤

1. 用户安装新构建的候选包，在“设置 → GlassFolders”点击“1. 复制设备码”，将 `GF-…` 设备码发给签发者。
2. 签发者在 Windows 独立工具填入设备码、授权编号和用户名称，可选填联系方式 / 备注，再点击“1. 生成绑定码并复制”，发给用户。绑定码有效期五分钟。用户资料仅保存到电脑本地历史记录，不包含在发送给手机的授权码中。
3. 用户点击“2. 绑定本机”，粘贴绑定码，生成并复制设备回执，再发给签发者。设备必须已解锁。
4. 签发者复制收到的回执，点击“2. 粘贴回执并验证”，在五分钟内点击“3. 签发授权并复制”。如已过期，从第 2 步重新开始。
5. 用户点击“3. 粘贴授权”，粘贴 `GF1.…` 授权，然后“应用并注销”。

全过程不依赖授权服务器。消息可以通过用户自己的方式传递。每个绑定码只能签发一次；历史授权可以从签发器中重新复制。移除授权后请注销，使所有已创建的文件夹背景恢复。

授权永久绑定本机，没有订阅到期时间。五分钟倒计时只约束绑定和签发过程，不是授权有效期。更换设备需要重新签发；更新插件时要保留同一签发公钥才能继续识别旧授权。

## 系统支持范围如何判断

原代码包依赖只声明 `firmware >= 16.0`，编译目标为 iOS 16.0、SDK 为 16.5。这能确定最低声明版本，不能证明所有更高系统都兼容，也不能把最高版本理解成 16.5。

| 系统 | 本候选版目标 | 当前证据 / 发布条件 |
| --- | --- | --- |
| iOS / iPadOS 16.0–16.7.x | 适配目标 | 代码最低版本满足；各设备与越狱环境仍需实测 |
| iOS / iPadOS 17.0–17.3.1 | 适配目标 | 已增加私有类继承和方法存在检查；玻璃效果、设置和绑定回执待真机验证 |
| 低于 16.0 | 不支持 | 部署目标和安装包依赖限制 |
| 17.3.1 以上 | 未纳入本次适配 | 候选包用 `firmware (<< 17.3.2)` 限制安装范围 |

这是需要 SpringBoard 插件注入的越狱 tweak。系统版本符合不代表任意设备都能安装；还需要该设备、该系统上可用的越狱与注入环境。单独安装 TrollStore 应用不能替代 SpringBoard 注入。

- **RootHide 包**：arm64e，必须配套 RootHide 环境。
- **标准 rootless 包**：arm64 + arm64e，必须配套标准 rootless 环境和 PreferenceLoader。不能用 RootHide 包代替。
- iOS 17 上哪些设备能运行取决于实际越狱支持，不能据此承诺所有 iPhone 在 17.3.1 都可使用。

对私有类的处理：`SBFolderIconImageView` 必须是 UIView 子类且存在 `setBackgroundView:` 才安装对应 hook；其他私有视图 / 控制器也验证 UIKit 继承关系。CAFilter 检查工厂方法；CABackdropLayer 检查 CALayer 继承关系；私有材料不可用时沿用已有的 UIKit 模糊回退。缺少私有入口时跳过相关功能，不能保证视觉效果完全一致。

## 发布前真机检查

至少在可用的 16.x 与 17.0–17.3.1 设备 / 越狱组合上分别记录系统、机型、越狱版本和包类型，然后检查：

- 设置页正常显示，中英文切换正常；未授权时文件夹和资源库都不应用插件效果。
- 设置进程与 SpringBoard 能读取相同的设备标识；绑定回执可生成，完整流程能激活。
- 另一台设备的授权、RC7 授权、改动过的授权均无法激活；重启 / 重新越狱后状态正确。
- 注销后：关闭的文件夹、展开文件夹、资源库卡片及搜索框均正常；明暗模式、旋转、横竖屏正常。
- 两种样式、强度和独立开关正常；移除授权后注销，恢复系统默认效果。
- 系统日志没有私有方法异常、Preferences 崩溃或 SpringBoard 重启循环。

## 协议和边界

- 设备码为 `GF-` 加 SHA-256(`GlassFolders-HW-v1|` + 16 位大写十六进制 UniqueChipID)。原始标识只在内存中使用，不写入文件或日志。哈希后的设备码仍属于可识别设备的数据，应仅用于授权。
- 最终授权是 `GF1.base64url(JSON).base64url(ECDSA-P256-SHA256-DER)`。JSON 只接受 `v/product/sid/device/ent` 五个字段，产品 `GlassFolders`，权限 `glassfolders`。
- 设备端与设置端均验证公钥签名和本机硬件码。不会信任可手动修改的“已激活”布尔值。验证在加载 / 刷新设置时进行，不在每帧绘制时进行。
- 绑定码 `GFC1` 含随机 nonce、设备码、签发时间和过期时间，默认 300 秒。`GFP1` 回执使用设备临时的不可导出 Secure Enclave P-256 密钥签名；签名消息前缀为 `GlassFolders-GFP1-v1\n`，随后是约定顺序的 JSON。不持久存储临时私钥，不降级成软件密钥。
- **回执验证的是回执签名密钥的持有者，不是 Apple 硬件证明。** 签发器不能仅凭回执独立确认其来自 Secure Enclave，也不能据此证明远端所声称的硬件身份。最终设备限制由插件本机硬件匹配实现。此流程用于防止误绑定、篡改与重放，不应宣传为硬件远程认证。
- 越狱环境和开源代码可被修改；本方案提供离线签名验证和设备限制，不提供不可破解保证。离线永久授权没有即时远程撤销机制。

## 自动检查

Windows 上安装 Node.js 后运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\Test-Issuer.ps1
```

Node 不在 PATH 时先设置 `GF_TEST_NODE` 为 node.exe 的完整路径。测试使用独立临时密钥，结束后清理临时目录，不使用正式签发私钥。私钥、签发记录均不应进入 Git 或安装包。
