# 通知与横幅的白底可读性候选实现

日期：2026-11-05。状态：此候选已撤回，不能作为用户现有 1.3.2 的升级包。它误用了旧的 1.3.0 实验分支；编译与文件完整性检查不能弥补基线错误。`../DEB/11-5` 的包仅保留追溯，禁止据此降级安装。后续必须以已验证的 1.3.2 源码迁移白底改动并重新构建。

## 本次变化

- 移除通知统一使用 35% 黑色遮暗的规则。
- 只在已识别的通知短卡片与横幅内，读取可见标签的实际颜色，包括富文本的前景颜色和前景分支透明度；不修改文字颜色、内容、过滤器或图标。
- 以普通 sRGB source-over 合成为模型，分别计算浅色及深色中性底板的保守对比度边界，选择满足所有已采集前景颜色且遮挡较少的一种。模型目标为 4.5:1，透明度上限为 72%；这些是本项目的工程参数，不是苹果或 Mango 的默认参数。
- 仅对选中浅色底板的通知实例，减弱白色亮肩和反光，加强既有窄内暗缘。圆角、描边宽度与几何算法不变；共享边缘默认参数保持原值。
- 只有系统明确表示通知内容已隐藏时，才使用后排轻量主体配方；不能单凭缩放变换降低可见文字的对比度保护。
- 无法安全分析文字、颜色配方冲突、需要过高不透明度或辅助功能要求更强可读性时，恢复并保留完整原生材质。
- 关闭、移除授权、离开适用场景及通知呈现类型切换时沿用现有恢复路径，不保留额外文字状态。

这不是局部壁纸亮度采样，也不声称实现了苹果完整的动态材质适配。白色文字通常会选择深色底板，深色文字通常会选择浅色底板；不会仅凭系统深浅模式猜测壁纸亮度。

## 安全边界

检查限定在当前通知宿主内，最多访问 128 个视图、10 层深度和 256 个前景颜色样本。隐藏分支、原背景和本插件玻璃分支不参与采样。遇到独立前景材质、compositing filter、其他图层滤镜或无法解析的颜色时，不猜测最终显示结果，而是回退原生。

没有新增截图、逐帧遍历、定时器、全局 UILabel / UIView hook，也没有复制 Mango 的实现。辅助功能状态变化及通知 trait 更新触发已有的事件式刷新。

音乐、实时活动、圆形按钮、Dock、文件夹和资源库不启用本次通知前景分析。独立开关、授权和偏好域保持原样。

## 实机检查

1. 同一白色壁纸比较原生外观与候选外观，确认应用名、正文、时间及次要文字均清楚。
2. 比较浅灰、彩色和纯黑壁纸，检查浅色底板轮廓、深色底板密度及是否过度遮挡背景。
3. 检查混合颜色、附件、富文本和隐私预览；回退原生属于预期保底，不应出现透明底板配不可读文字。
4. 测试折叠后排、展开、滑动删除、连续横幅及深浅外观切换，观察是否有配方切换闪烁或后排叠黑。
5. 开关“降低透明度”和“增强对比度”，确认及时恢复原生；关闭后重新校验是否可安全使用候选配方。
6. 关闭插件开关、切换通知呈现类型和移除授权，确认原背景及原堆叠装饰恢复，内容与交互不变。
